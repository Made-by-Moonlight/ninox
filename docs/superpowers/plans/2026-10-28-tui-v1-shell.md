# ninox-tui v1 Shell Replacement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace ninox-tui's entire tab/screen set (`Fleet/Overview/PRs/Brain/Settings/Graph/WT`) with the v1 design's six tabs (`Fleet/Board/Plans/Brain/Worker Types/Remotes`), per MLOPS-5350.

**Architecture:** Today's `View::Graph` (tree+canvas+prompt+detail, already fleet-wide, already has graph node rendering/prompt/compact-toggle/depth-ring/health-badge from #230/#241/#243) becomes the new `View::Fleet`, gaining today's `View::Board` sidebar (richer: NEEDS YOU grouping, per-row metadata, close button) as its Tree region and a session-attach "pane" mode reached by pressing Enter on a selected node. Today's `View::Board`/`View::Overview`/`View::PrWatches` retire as tabs. A new 6-column kanban (`kanban.rs`, modeled on `ninox-gui`'s `fleet_board.rs` column/fold logic, not shared code) becomes the new `View::Board`. `View::Plans` ships as a minimal empty-state tab (the real cross-fleet plan-review backend is explicitly a non-goal of the design spec — see Global Constraints). A new `View::Remotes` lists already-collected-but-unrendered machine config + health data (`remotes.rs`). `View::Settings` moves from a tab to a `Modal::Settings` variant. `View::WorkerTypes`/`View::Brain` keep their existing screens, repositioned in the tab order.

**Tech Stack:** Rust, ratatui, the existing `ninox-overview` crate (already merged, do not re-derive its island/status/nav model — that's MLOPS-5351, explicitly out of scope here).

**Spec:** `docs/superpowers/specs/2026-10-21-fleet-overview-ui-vision-design.md` (sections: Navigation, Screen skeleton, Fleet at scale [out of scope for this PR], Plan review, Worker types), plus `/Users/ethan.brodie/proj/ninox/.claude/design-ref/fleet-overview-v1/BRIEF-common.md` and `BRIEF-MLOPS-5350.md` (ticket-specific brief; where it differs from the spec, the brief wins per its own header). Design artboards: `TUI.dc.html`, `Legend.dc.html`, `TUIAtScale.dc.html` (tab bar order only — its graph content is PR2/MLOPS-5351 scope).

## Global Constraints

- Exactly six tabs, this order, these labels, keys `1`-`6`: `Fleet`, `Board`, `Plans`, `Brain`, `Types` (tab-bar label; the screen's proper name is "Worker Types" per spec §Worker types), `Remotes`.
- Tab bar must not silently drop a tab at 80 columns (`layout.rs`'s `tabs()` width-budget bug, see project memory `tui-header-tab-width-budget`): recompute `BADGE_W(10) + Σ(label.len()+4) + (n-1)` for the 6 new labels against `STATUS_W(16)` and an 80-col terminal before picking final label text.
- No horizontal overflow at 220×60 or 120×40 (ticket acceptance criterion).
- `View::Settings` is removed from the tab bar; reachable only via a key/command, as a modal.
- `View::PrWatches` (`prs.rs`'s list screen) is removed entirely; PR state must remain visible per-session (today's `pr_state_color`/`state_word` logic, `view.rs:1013-1023`/`prs.rs:116-126`, migrates onto the per-node/per-kanban-card rendering, not deleted).
- Keep unchanged (from #230/#241/#243): graph node rendering, the ninox prompt + answers, the compact toggle, the depth-cap ring, the remote health badge — all in `graph.rs`, reused as-is.
- Do not re-derive the fleet island model; island/at-scale rendering (`ninox_overview::islands`) is MLOPS-5351/PR2 scope, not this PR.
- Do not modify any `crates/ninox-gui/**` file. `fleet_board.rs`'s `COLUMNS`/`column_absorbs` (lines 15-22, 65-76) are reference-only for porting the fold logic into `ninox-tui`'s own `kanban.rs`.
- Branch from (now-current) `origin/v1`, PR targets `v1`, PR title `MLOPS-5350: type(scope): description`.

## Review Focus

- A terminal narrower than 80 columns (e.g. 72, 64 cols): the tab bar must not silently drop a tab — test at the narrowest width the existing suite checks, updated for 6 tabs.
- A session with `pr_number` set but registered via `ninox open --pr` only (no owning session found, `prs.rs:63-85`'s "watch-only" row): after the PR list is deleted, this case has no per-node home (it isn't attached to any live session) — must not silently vanish; decide and implement a fallback (surfaced as a notice, or folded into Remotes/Board, not dropped).
- Zero live sessions: `Fleet`, `Board`, `Plans`, `Remotes` must each render a sane empty state (reuse `view.rs::empty_state`), not panic on empty `rows`/`nodes`.
- A now-removed letter shortcut (`'o'` → Overview, `'p'` → PrWatches) must be removed from `command()`, not silently dispatch into a deleted view.
- Opening the Settings modal while `Focus::Pane` has a live session attached: keys must route to the modal (like `Modal::Help`/`Modal::Confirm` already do), never leak into the pty.
