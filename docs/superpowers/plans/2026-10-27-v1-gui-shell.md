# MLOPS-5339: v1 GUI shell (ninox-gui)

PR 1 of a multi-PR replacement of the ninox-gui app shell. Design source of
truth: `docs/superpowers/specs/2026-10-21-fleet-overview-ui-vision-design.md`,
the design artboards in `.claude/design-ref/fleet-overview-v1/` (raw HTML —
exact hex tokens and layout pulled directly from `Legend.dc.html`,
`Main.dc.html`, `FleetAtScale.dc.html`), and `BRIEF-common.md` /
`BRIEF-MLOPS-5339.md` in that same folder (final, authoritative; supersede
the ticket text where they differ).

## Scope (this PR)

- New dark v1 design tokens, GUI-local (not wired into the existing
  `ThemeVariant`/`Themes`/theme-file system in `ninox-ui-shared`, which
  stays untouched — shared with `ninox-tui`, out of scope here, and the
  existing light/dark/"ninox"-alias picker still governs legacy screens
  this PR doesn't reskin).
- New top nav: brand + six tabs (Fleet · Board · Plans · Brain ·
  Worker Types · Remotes) with number-key hints, search box, settings gear.
  Nav markup/styling follows `FleetAtScale.dc.html` (text-only tabs, no
  per-tab icons) — the newer, 27-Oct board — not `Main.dc.html`'s older
  icon-nav, which also lacks the Board tab entirely.
- New three-column body: collapsible session tree (left, ported from
  `sidebar.rs`'s tree data/expand-state, restyled) | centre (tab content) |
  detail panel (right, empty-state container in this PR — real content is
  PR 4).
- Bottom context-action row: empty/generic in this PR (real per-selection
  actions start with islands in PR 2+).
- **Board** tab = today's Kanban (`fleet_board.rs`), restyled with v1
  tokens, mounted unchanged in behavior.
- **Fleet** tab = plain placeholder centre content. (No existing GUI graph
  to carry forward: the only prior "fleet overview" graph code lives on
  the rejected, unmerged sibling branch `v1-mlops-5339-gui-fleet-overview`
  and is not part of this worktree — confirmed via `git log`/`grep`.
  Orchestrator-clarified: placeholder is correct here.)
- **Brain** tab = existing `brain_panel.rs` content, relocated only (not
  reskinned — no board depicts Brain's internals; out of scope).
- **Plans**, **Worker Types**, **Remotes** tabs = new, simple placeholder
  centre content (no existing GUI implementation for any of the three).
- **Removed:** `components/sidebar.rs` (cream masthead/TOC/footer),
  `components/pr_list.rs` + `View::PrList`, `components/workers_view.rs` +
  `View::Workers`. Nothing to remove for the interim "V. Fleet overview"
  section — it was never merged into this branch's history.
- `View::SessionDetail` keeps today's behavior (full centre-column
  takeover, chrome persists around it) — restyling/moving it into the
  right detail panel is PR 4.
- `View::Settings` keeps today's behavior, reached via the nav's gear icon
  (matches the mockup) instead of the old sidebar footer link.

## Open judgment calls (noting per brief instructions, not re-litigating)

1. **Theme wiring**: two layers, not one. The shell chrome (nav/tree/
   detail-panel/bottom-bar/prompt) uses new GUI-local pixel-exact
   constants (`components::shell::tokens`) since the v1 palette's shape
   (explicit status/connection colors, a ghost-violet with no prior
   analog) doesn't fit the existing `ColorScheme`'s 28-field model.
   Everything still on the old `ColorScheme` (Board, Brain, session
   detail, terminal, settings) gets the v1 colors for free instead: GUI's
   own `theme::dark()`/`Themes` (`ninox-gui/src/theme.rs`, NOT
   `ninox_ui_shared`) now overlay the v1 hex values onto the shared dark
   base for the surface/ink/accent/status fields, leaving `cat_*`/`term_*`
   alone. `ninox_ui_shared::theme` itself is untouched, so `ninox-tui`'s
   dark theme is unaffected. Net effect: "Dark" and "Ninox" (already an
   unused alias of Dark) now both render the v1 look; this intentionally
   overrides a user's theme-file dark-palette customization, since v1 is
   a full visual replacement.
2. **Nav reference board**: followed `FleetAtScale.dc.html` (has Board,
   text-only tabs) over `Main.dc.html` (no Board tab, icon tabs) since the
   former is the later, 27-Oct "real state" board and matches
   `BRIEF-common.md`'s decision text exactly.
3. **Nav-bar extras**: kept Spawn (+) and Alerts (bell) as `.nav-icon`
   buttons next to Settings (gear) — existing must-keep features with no
   mockup showing where they relocate to; `.nav-icon` is an established
   class in the design CSS, used today only for the gear.
4. **Tree collapse persistence**: one manual `[` / rail-button toggle,
   default collapsed (since the default tab is Fleet). No automatic
   re-expand when switching tabs — simplest reading of "starts collapsed
   on the Fleet tab" that doesn't invent cross-tab state rules the brief
   doesn't specify.

## File-level changes

- `crates/ninox-gui/src/components/shell/` (new): `tokens.rs` (v1 color
  constants + status/connection color helpers per `Legend.dc.html`),
  `nav.rs`, `tree.rs`, `detail_panel.rs`, `bottom_bar.rs`, `placeholder.rs`,
  `mod.rs` (assembles the four regions around a passed-in centre
  `Element`).
- `app.rs`: `View` enum — rename `FleetBoard{scope}` → `Board{scope}`
  (and `Message::NavigateFleet{scope}` → `NavigateBoard{scope}`, all call
  sites below) to free up `Fleet`/`NavigateFleet` for the new tab; add
  `Fleet`, `Plans`, `WorkerTypes`, `Remotes` variants/messages; remove
  `PrList`/`Workers` variants/messages; change `View::default()` to
  `Fleet`; add `tree_collapsed: bool` to `App`, default `true`; route
  `iced_view` through `components::shell` for the six tabbed views, keep
  `SessionDetail`/`Settings` as today; update the `"1".."5"` keyboard
  shortcuts to `"1".."6"`.
- `fleet_board.rs`: restyle to v1 tokens; update its internal scope-chip
  navigation to `Message::NavigateBoard`.
- `session_detail.rs`: update its "back" button to `Message::NavigateBoard`.
- Delete `components/sidebar.rs`, `components/pr_list.rs`,
  `components/workers_view.rs`; remove their `mod` lines and all
  references.
- Update every test in `app.rs` referencing the renamed/removed
  variants/messages.
